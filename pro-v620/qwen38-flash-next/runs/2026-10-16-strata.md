# Qwen3.8-Flash-Next: Strata in place of llama.cpp on one card

Plan committed 2026-10-16 · Run — · Status: planned

## Question

Does [Strata](../../strata/README.md) v0.1.44.1 serve Qwen3.8-Flash-Next UD-Q4_K_XL on GPU 2
(CT 123, one V620, `0000:83:00.0`) faster than the deployed llama.cpp configuration, with
correct output? Which Strata settings are fastest on this box?

What Strata does differently from llama.cpp's `-ncmoe 37`:
- It keeps every routed expert in a page-locked RAM arena.
- It fills the VRAM left after the dense weights with an expert cache that adapts to the
  requests.
- The CPU computes the cache misses while the GPU works.
- It drafts with the model's MTP layer, built from the BF16 checkpoint.

Strata's own measurements, which this run does not reproduce:
- **The closest box to ours** (Radeon AI PRO R9700 32 GB, RDNA4; EPYC 7452 with eight
  DDR4-2400 channels; UD-Q4_K_XL; every expert in RAM): 63–64 t/s decode on a story,
  85–88 on code, 1,110–1,320 t/s on a 32K prompt. llama.cpp on the same card and file:
  18–20 t/s decode, 198–257 t/s on a 4K prompt (docs/QUANTS.md at the pinned commit).
- **The same chip as the V620** (one RX 6900 XT 16 GB, gfx1030, GSQ-RCO IQ3_S, engine 0.1.41,
  community report): 46–52 t/s decode, 850–1,103 t/s prompt with the two RDNA2 switches
  (bench/results/2026-10-09-community-2x-rx-6900xt-0.1.41).

RDNA2 differs from RDNA4: no matrix cores, the older dot4 instruction, and no hipBLASLt
kernels.

The deployed llama.cpp configuration (b11505, `-ncmoe 37`, `dio`, Q4_K_M MTP head at n-max 3,
one 64k slot) measured 347–360 t/s prefill at d8000 (~5.8k tokens) and a median 18.1 t/s
decode through `/completion`
([prefill-slowdown record](2026-10-10-prefill-slowdown.md), stage 2, `h37`). In the full
batch, its agent sessions took 532 s (`hermes`) and 388 s (`coding`) (same record, stage 3).

## What answers it

**Gate (stage 1).** No speed result counts until all of these hold:
- Strata's quality yardstick (`tools/quant_quality.py run`, 4,995 teacher-forced positions of
  `data/quant_quality/v1`) gives a perplexity within 2% of 4.068. That is Strata's figure for
  this file on an R9700 through HIP (docs/QUANTS.md). Open issue
  [#2457](https://github.com/Niko1221/Strata/issues/2457) (0.1.44 output turns to garbage on
  RX 6000 cards with IQ3_S) would show as far more than 2%.
- The chat contract passes with the draft layer on and off, for efforts `none`, `low`,
  `medium` and `high`: every reply is non-empty, and no `<think>` tag leaks into `content`.
- A tool call returns a parsable call to the declared tool with JSON arguments, both
  streamed and not, with the draft layer on and off.
- No probe row is empty, degenerate (the probe's 8-gram gate) or cut off without tokens.
- The engine log of every cell has no `stall report`, `timed out at layer`,
  `no progress for` or `non-finite logits` line.

**A setting** (stages 1–6) is kept for the later stages when both hold:
- Its median decode beats the stage's control beyond both cells' pass-to-pass spread. Decode
  is per prompt class and depth, and the comparison is the median across the cell's rows.
- No depth's cold prefill falls more than 10%.

A prompt-path switch is kept when cold prefill at d8000 and d32000 rises beyond both spreads
and decode stays within them. A switch that changes numerics is reported with its prompt-path
KL against the default path (`quant_quality.py prompt` and `pcompare`). This applies to
`STRATA_HIP_PROMPT_F16`, `STRATA_MMQ_KQ` and `STRATA_DENSE_MMQ`; whether one is deployed is
the owner's decision.

**Strata against llama.cpp (stage 7).** For each measure, the ratio of medians, counted as a
difference only beyond both engines' pass-to-pass spreads:
- decode per prompt class at d0, d8000 and d32000;
- cold prefill and time to first token at each depth;
- two-stream aggregate decode, and the second stream's time to first token.

The usage test is `make bench GPU=2 MODEL=strata` at the configuration this record finds best,
in its own record. It is judged by the owner's keep rule from the
[2026-10-10 batch](2026-10-10-bench.md#deviations) against the deployed configuration's batch
(the [prefill-slowdown record](2026-10-10-prefill-slowdown.md), stage 3).

A cell with any DIMM sample at 66 °C is reported as capped and not used for a decision.

## Configurations

**Model files.** UD-Q4_K_XL, the four shards llama.cpp serves
(`/models/hf/qwen3.8-flash-next/`). Their SHA-256s are those of the revision Strata
supports, so no other quantization is downloaded. Strata adds two things:
- a pack of shard 1: the dense weights rounded where its loader needs BF16, and the
  tokenizer;
- its MTP draft layer, about 5 GB of the BF16 checkpoint's `mtp.*` tensors with Q2_0
  experts.

Unsloth's MTP heads are a llama.cpp format and are not used.

**Starting configuration** (`strata-qwen38fn.env` at this commit): setup.py's choice for this
box, plus the three RDNA2 switches; settings and sources are in the
[Strata README](../../strata/README.md#configuration). Each stage starts from the previous
stage's kept settings, which the Results name. Stages 1–6 have cell files beside this record
(`2026-10-16-strata-<n>-<stage>.cells`).

| Stage | Cells | Varies |
| --- | --- | --- |
| 0. Setup | none | Install, `use-engine.sh strata`, `strata-device --selftest`, ctest, the harness |
| 1. Gate and screen | `base` (setup.py's config, `STRATA_HIP_ADAPT_KERNEL_COPY=1` only); `rdna2` (+ `STRATA_HIP_PROMPT_F16=1`, `STRATA_SH_STREAM=1`); `rdna2-mtp` (+ the draft layer at `--spec 4 --spec-min-p 0.5`, for the gate and its VRAM only) | The RDNA2 switches |
| 2. Prompt path | `mmqkq` (`STRATA_MMQ_KQ=1`), `densemmq` (`STRATA_DENSE_MMQ=1`), `chunk16k` (`--prefill auto:16384`) | Prompt kernels and chunk size |
| 3. Memory placement | `ple-ram` (`--ple-io ram`), `kv-vram` (no `--kv-resident`: all 64k of KV in VRAM) | Where the n-gram table and the KV cache live |
| 4. CPU workers | `w11`, `w15` (control), `w19`, `w23` | `--pool-workers` on CT 123's 24 CPUs |
| 5. Context and slots | `ctx128k` (`--max-context 131072`); `p2` (`parallel: 2`) against one slot, both at two streams | Context and batch slots |
| 6. Speculative decoding | control (no draft layer, `--suffix-draft 0`); suffix drafts alone; MTP `--spec` 1, 2, 3, … at `--spec-min-p 0.5` until decode has clearly fallen past its peak, then the best ±1 at `--spec-min-p` 0.3 and 0.7; with `p2`, also `--batch-mtp` | Drafters, draft length, threshold |
| 7. Against llama.cpp | `strata-best` (stage 6's result); `llamacpp` (the deployed `qwen38fn-gpu2.env`) | Engine |

Stages 1–5 run without the draft layer and with suffix drafts off (`--suffix-draft 0`), so
their decode compares settings rather than draft acceptance. Speculative decoding is the
last stage, on the settled configuration: the draft's VRAM and best length depend on
everything before it, as llama.cpp's head did ([MTP experiment](../README.md#mtp-experiment)).
Only `rdna2-mtp` loads it earlier, to check that it works and what VRAM it takes.

The standard configurations:
- **One GPU:** every stage. This is the question.
- **Two GPUs:** left out. The owner keeps GPU 1 for CT 120 and Hermes (2026-10-10), and
  Strata's layer split pays only when no single card holds the cached experts.
- **CPU only:** left out. Strata needs a GPU.
- **Optimized, leaving resources free:** left out. GPU 2 serves one model, and
  `--expert-cache auto` sizes the cache to the VRAM that is left.

Drafters: Strata's MTP draft layer and its suffix (prompt-lookup) drafts. Stage 6 measures
each against the no-draft control at one and two streams and quotes acceptance. There is no
DFlash drafter for Flash-Next in Strata. Suffix drafts pay only on text the reply repeats, so
the usage test's agent sessions, which edit code, are where they show.

## Controls

- Every stage has its control cell (the previous stage's kept settings), interleaved with
  the other cells, three passes, each load cold.
- `llamacpp` in stage 7 is the deployed env (`qwen38fn-gpu2.env` at main `0b73cfd`), in the
  same chat-mode probe, interleaved with `strata-best` by `use-engine.sh` between passes.
- Same model files (verified SHA-256), card, 250 W cap, 0 mV offset and `schedutil`
  governor for both engines; `capture-env.sh` records them.
- Output: the gate above, and the quality yardstick again on `strata-best`.

## Method

**Stage 0 builds what the run needs and is committed before stage 1:**
- `strata-sweep.sh`, the Strata counterpart of `placement-sweep.sh`. A cell is
  `LABEL KEY=VALUE …` over the env file's keys (`MODEL_*`, `STRATA_*`). Per cell it:
  - rewrites `/etc/strata-qwen38fn.env` and restarts `strata-qwen38fn`;
  - waits for `/v1/models`, records the load time;
  - reads from the engine log the expert-cache slots, the VRAM-free line, the hit rate at
    stop, and any stall or non-finite line;
  - runs the probes in chat mode, and samples power, clocks, VRAM/GTT, CPU and the hottest
    DIMM per phase, as the placement sweep does;
  - restores the env file and the service state on exit.
  It keeps the thermal-trip file, the 58 °C DIMM start gate and `UNPINNED` refusal of the
  placement sweep.
- `placement-probe.py` and `concurrency-probe.py`: a per-request nonce at the start of each
  prompt, since Strata ignores `cache_prompt`; rows with `cache_n` above 0 fail unless
  `--cache`; and Strata's efforts (`none,low,medium,high`).
- A tool-call check (streamed and not) beside the contract check.
- `capture-env.sh`: the Strata engine commit and binary SHA-256, the ROCm package versions,
  `/etc/strata-qwen38fn.env`, the JSON config and `strata-device --list-devices`.
- `ansible/benchmark.yml`: a `strata` model (`strata-qwen38fn`,
  `/usr/local/bin/strata-qwen38fn-reload`) for the usage test.

**Run:** from `/root/harness/<sha12>/pro-v620/qwen38-flash-next/` (`../push-harness.sh`),
per stage:

```bash
VMID=123 UNIT=strata-qwen38fn ./thermal-guard.sh          # separate shell
VMID=123 CELLS=runs/2026-10-16-strata-<stage>.cells PROBE_CHAT=true \
  DEPTHS=0,8000,32000 REPS=1 PASSES=3 ../strata/strata-sweep.sh
```

- Prompt classes `code`, `list` and `prose`, 256 tokens each, greedy. d8000 is ~5.8k
  tokens and d32000 ~23k; the summary prints measured sizes.
- One warm-up request per load is left out: Strata's first fresh prompt after a start
  reads slower (docs/AMD_HIP.md, tuning-table notes).
- Besides env-file keys, a cell takes `STREAMS` (adds the concurrency probe with that many
  streams, `CONC_REPS=3`) and `CT_MEMORY_MIB` (CT 123's memory for that cell, set back to
  122880 after it).
- Stage 7 runs three rounds, each a llama.cpp pass and a Strata pass with the same probe
  arguments and nonce seed:
  - `./use-engine.sh llamacpp`, then `placement-sweep.sh` with one cell, the deployed env;
  - `./use-engine.sh strata`, then `strata-sweep.sh` with one cell, `strata-best`.
- `vram-residency-sampler.py --pci 0000:83:00.0` runs beside every stage.
- The yardstick runs between stages, with the server stopped:

```bash
pct exec 123 -- systemd-run --wait --pipe -p User=llamacpp -p SupplementaryGroups=render \
  -p LimitMEMLOCK=infinity -p WorkingDirectory=/opt/strata/strata-v0.1.44.1 \
  /opt/strata/venv/bin/python tools/quant_quality.py run \
  --config /var/lib/strata-qwen38fn/config.json --out /models/strata/quality/<label>.tsv
```

The config is the one the cell's server last wrote; the yardstick fixes its own cache,
adaptation, KV and tail-skip settings (`FIXED` in the script).

The duration is unknown until stage 1 measures a load and a cell; the record adds the
estimate for the remaining stages there. Raw data lands in
`/root/qwen38-flash-next/strata-sweep-<ts>/` on the host.

## Safety

- Every other guest stays shut down: CT 120 `llamacpp`, CT 121 `hermes`, CT 140 `kb-rag`,
  CT 200 `bench-runner`, CT 201 `llamacpp-builder` and VM 300 `docker-host` are stopped
  already (2026-10-16 11:48 ET). They wait for the owner to restart them.
- `use-engine.sh strata` moves the watchdog's `0000:83:00.0` entry to `123:strata-qwen38fn`
  and `use-engine.sh llamacpp` moves it back; `thermal-guard.sh` runs beside every stage. A
  trip stops the stage; cooling is checked before anything restarts.
- CT 123 holds only GPU 2's render node, so HIP sees one device. The launcher refuses to
  start unless `strata-device` lists exactly one gfx1030.
- Memory: the arena (77 GB) and the engine fit CT 123's 120 GiB. `ple-ram` needs about
  29 GB more. For that cell CT 123 is raised to 160 GiB (`pct set 123 -memory 163840`,
  live), with `MODEL_MEMORY_LIMIT_MIB` raised to match, and set back to 122880 afterwards.
- At the end, `use-engine.sh llamacpp` restores the deployed server. A request then checks
  free VRAM and GTT against the deployment notes: 3,271 MiB free, with GTT holding the
  pinned experts.
